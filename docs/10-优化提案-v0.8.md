## 1. 优化点清单

优先级：**P0** = 下一版（0.8.0）就做；P1 = 0.9；P2 = 有空再说。
工作量：**S** 半天内 / **M** 1–2 天 / **L** 3 天以上。

### 甲、名实相符：把"写着 AI、其实不是"的地方变真

#### A1 玉简真回信　P0　M

- **问题（证据）**：玉简面板文案写"发信将由 AI 生成回信"，实现却是三条写死台词里抽一条（`prototype/app.js:2552` `const reply = pick([...])`）。发第二条就会发现回信在循环——货不对板。
- **方案**：复用现有流式对话管道，一个固定小提示词：联系人卡（姓名/关系/好感/最近 3 条记录）+ 玩家新消息，`max_tokens ≈ 120`，走叙事槽采样。回信流式进气泡；失败**降级为"传讯未达"**并保留原文可重试，绝不假装发出去了。
- **验收**：真机给已有联系人发两条不同的话，回信与上下文相关；断网/Key 失效时是可读错误。
- **成本**：每条消息一次小调用，计入 B1 的账单。

#### A2 器灵台词启用　P2　S

- **问题（证据）**：初始状态里有 `'$器灵台词'`（`prototype/data.js:86`），UI 全程不读——卡里现成的氛围资产闲置。
- **方案**：三处消费，全部引擎随机、不调模型：①突破成败飘字；②同会话闲置超 2 分钟 HUD 边缘低语一次；③时间线回看里作旁注。

### 乙、成本与延迟可见

#### B1 每回合账单　P0　S–M

- **问题（证据）**：管道断在最后一米——Rust 已 `include_usage` 并解析（`app/src-tauri/src/llm.rs:331,467`），bridge 定义了 `usage` 事件（`prototype/bridge.js:38`），但 **app.js 没有任何一处消费**。一回合花多少 token、等了几秒，玩家全然不知。
- **方案**：①回合末尾一行小字 `≈3.2k tok · 8.4s`（点开看分层：提示词/输出各占多少）；②「设置 → 用量」累计视图（本档 / 全局，按日），持久化；③渠道若返回 `cached_tokens`（OpenAI 兼容字段）就显示"缓存命中 x%"——这是 B2 的前提。
- **验收**：真机一轮后数字出现、量级与渠道后台一致；累计跨重启不丢。

#### B2 前缀缓存省钱　P1　S+M（依赖 B1）

- 分层提示词（L0/L1 稳定前缀）本就是为缓存设计的，但**没有计量就不知道渠道是否真给了缓存折扣**。
- 先只观测：保证前缀字节级稳定（时间戳/随机宏不进前缀），看一周 `cached_tokens`：命中高就在预设面板标注"该渠道支持缓存"；不命中也无损失。**不为缓存重构层序，数据说话。**

### 丙、上手体验

#### C1 首启三步向导　P0　M

- **问题（证据）**：配渠道要自己摸到「模型」面板。拉模型列表（`prototype/app.js:1435`）算事实测连，但 **`/models` 通 ≠ 对话通**——中转渠道常按路由分开鉴权：列表能拉、聊天 401。
- **方案**：首次进入（无 Key 且无存档）弹三步：①选渠道（内置常见预设 + 自定义）；②填 Key；③**「测连」＝发一条 `max_tokens=1` 的真实对话请求**，错误翻译成人话：401 → Key 不对；超时 → 地址不对或网络不通；404 → 路径不对。每步可跳过（先逛图鉴）。
- **验收**：全新安装 60 秒内配好并听到第一段叙事；三种典型错误各给一句可读提示。

#### C2 空状态指路　P2　S

- 图鉴 / 成就 / 绝色榜空面板各补一句"怎么解锁"（玉简 0.2.0 已做，照那个样式；动手前先核对 0.7 的交互实测有没有覆盖）。

### 丁、移动端手感

#### E1 安卓返回键　P0　M（小而痛）

- **问题（证据）**：README 已知项依旧在——按返回**直接退出应用**，抽屉、弹层、全屏页都不收（全仓 grep 无 back 拦截）。手机上这是最容易被当成 bug 的行为。
- **方案**：按层次收：更多弹层 → 侧栏抽屉 → 全屏页 → 最后"再按一次退出"。实现两选一（Tauri Android 的 back 回调 / JS history 钩子），以能落地的为准。
- **验收**：真机逐层返回不退出、不闪退。

#### E2 软键盘避让复查　P2　S

- visualViewport 三重监听早已接；只补三类机型抽查，与 `docs/09-交互实测审查` 的"无法验证项"合并成一次真机回归。

### 戊、安全与分发

#### F1 Android Keystore　P1　M

- 现在是"随机主密钥文件 + AEAD"（防拷贝/防明文）；下一步硬件级（Android Keystore / StrongBox），`docs/03` 既定方向。迁移要兼容老密文（现有版本头分派机制够用）。

#### F2 CI 直接出签名包　P1　S＋**需要你决策**

- 前提：你把 keystore 放进 GitHub Secret（`KEYSTORE_BASE64` + 口令 + alias）。放了，`release.yml` 加一步签名，Release 附件直接可装；不放就维持"本地签名 + 手工上传"。密钥进不进 GitHub 由你定。

#### F3 Windows 安装包自动挂 Release　P2　S

- `build-artifacts.yml` 已有 windows job（msi/nsis），产物现在要手动取；改成自动挂到对应 Release。

### 己、玩法深度（纯产品）

#### G1 命途统计面板　P1　M

- `$log` 已记录每次掷骰/突破/斗法——汇总成"突破成功率、越阶压制经历、闭关总天数、气运抽取次数、**斗法战绩**（0.6 新引擎的数据正好有地方去）"。给长局成就供数，也给玩家一个"我这一世"的回望入口。

#### G2 成就 → 奖励联动　P2　M

- 引擎侧一张映射表：指定成就给小加成（气运 +1 次、机遇优先级微调）。全确定性，不过模型。

#### G3 章节导出　P2　S

- 时间线选一段导出 txt/md 分享。存档导出 JSON 已有，这是叙事层的出口。

## 2. 建议的 0.8.0 范围

主题：**看得见（B1）、上得手（C1、E1）、名实相符（A1）**——四件全是用户当天能感知的事，互相独立、可并行、各自带验收：

| 项 | 一句话 | 工作量 |
|---|---|---|
| B1 每回合账单 | token / 耗时 / 缓存命中 + 用量累计 | S–M |
| C1 首启向导 | 三步配好渠道，测连错误说人话 | M |
| E1 返回键 | 逐层收起，不再一键退出 | M |
| A1 玉简真回信 | 删掉三条写死台词，接真模型 | M |
| A2 器灵台词（顺手捎上） | 突破/闲置/时间线三处启用 | S |

0.9：F1 Keystore、F2 CI 签名包（若你同意放 Secret）、G1 命途统计、B2 缓存观测。
再往后：G2、G3、F3、C2、E2。

**明确不做（任何版本）**：多语言、TTS、语音、云端账号与服务端、给叙事加图像生成——与"本地优先、零依赖、数据在玩家手里"的定位冲突，或收益配不上复杂度。

## 3. 整版验收方式

1. 每项按各自验收标准；
2. 浏览器回归 + 模拟器真机各过一遍，含固定动作"**每个面板至少打开一次**"（玉简那次教训）；
3. 全测试绿（前端 + Rust + 语法检查），新增行为补回归测试（账单数字、向导错误分类、返回键层次、玉简失败降级）；
4. 走一遍成熟的 tag → Release 管道发版。
