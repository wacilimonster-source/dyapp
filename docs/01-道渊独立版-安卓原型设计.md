## 0. 这份文档解决什么

主方案的界面章节（第 5 节）是**桌面优先**的（Tauri + Web，一张桌面线框图）。本次要回答三个新问题：

1. **同一套界面如何在手机和平板上各自成立**（不是把桌面缩小，而是两种版式）；
2. **每个页面在两端的线框长什么样、怎么跳转**（可直接照着实现）；
3. **落地到安卓的工程约束**（断点、安全区、返回键、横竖屏、WebView/包体、权限）。

一句话结论：**手机走「单栏叙事 + 全屏抽屉」，平板走「左导航 + 中叙事 + 右状态」三栏。** 二者共用同一套组件与状态层，只换骨架。

## 1. 安卓设计基线

### 1.1 设备分级与断点

原型只区分**两种版式**，由屏幕宽度决定，不猜设备型号：

| 版式 | 判定条件 | 典型设备 | 骨架 |
|---|---|---|---|
| **手机版式** | 视口宽 < 700px | 5.5"–6.8" 手机（360–480dp） | 单栏：HUD → 叙事流 → 行动区；面板为全屏抽屉 |
| **平板版式** | 视口宽 ≥ 700px | 8"–13" 平板（600–1280dp） | 三栏：左导航栏 + 中叙事 + 右状态面板 |

- 阈值取 **700px** 而非 820px：8 寸平板竖屏（CSS 宽约 800）也要落进平板版式，不能因为"竖着拿"就退回手机单栏。
- **大屏手机横屏**（约 800–900px）会进入平板版式——这是有意的，横屏手机看三栏比单栏更合理。
- 平板版式内部再分一档：**竖向时右栏收窄到 320px**（竖向可用宽度小），横向时 372px。

### 1.2 方向（Orientation）

| 版式 | 竖屏 | 横屏 |
|---|---|---|
| 手机 | **主场景**，叙事阅读最舒适 | 允许，但行动区变矮；不强制锁定 |
| 平板 | 支持（右栏收窄） | **主场景**，三栏最舒展 |

- 不锁定方向：安卓用户习惯横竖随手切，锁死会挨骂；只在**判定演出/创角抽取动画**时用一个全屏覆盖层，天然无方向问题。
- 用 `resize` + `orientationchange` 实时重算版式；重算时**保留滚动位置与当前面板**，避免旋转后跳回顶部。

### 1.3 安全区与触控

- 全站启用 `viewport-fit=cover` + `env(safe-area-inset-*)`：顶部让开状态栏/刘海，底部让开手势条。HUD 顶栏、抽屉头、行动区、底部按钮均已叠加安全区 padding。
- **最小触控目标 44×44dp**；行动区按钮、面板 tab、开关均按此实现。
- 字号基线 15px，标题/正文用 `Noto Serif SC`（离线内置，见 5.4），数值用等宽数字（`tabular-nums`）避免跳动。
- 所有列表与滚动容器启用 `overscroll-behavior: none` + 自定义滚动条，避免安卓 WebView 的橡皮筋回弹与"滚动穿透"。

### 1.4 配色与视觉基调（沿用卡片）

直接继承卡内状态栏 `regex6` 的变量，保证"还是那个道渊"：

| 用途 | 值 |
|---|---|
| 背景 / 深背景 | `#0d1220` / `#080c16` |
| 卡片 / 次级卡片 | `#151d31` / `#1a2338` |
| 描边 | `#2a3a5e` |
| 鎏金（主强调） | `#d4af37` |
| 冷紫（次强调） | `#c58aff` |
| 正文 / 次要 / 弱化 | `#e8e6df` / `#8b94a8` / `#5b6478` |
| 六维条 | 生命 `#e05555` · 精血 `#b0453a` · 灵力 `#5aa9ff` · 修为 `#d4af37` · 神识 `#c58aff` · 道心 `#6fd49a` |
| 危机四档 | 低 `#6fd49a` · 中 `#ffb066` · 高 `#ff7a6b` |

## 2. 信息架构与导航模型

### 2.1 页面树（与主方案一致，标注两端承载方式）

```
启动
├── 主菜单 ....................... 两端：居中卡片列表
├── 创角向导（6 步）............... 两端：单列步骤条（平板限宽 720 居中）
├── 游戏主界面 ★ ................. 手机：单栏 ／ 平板：三栏
│   ├── HUD 顶栏 ................. 手机：2 行紧凑 ／ 平板：六维一行
│   ├── 叙事流（中央）
│   ├── 行动区（底部）............. 手机：6 格轮盘 ／ 平板：8 格
│   └── 面板 ×11
│       ├── 主角 道侣 人物 灵宠 机遇 绝色榜 玉简 背包 地图 图鉴 设置
│       │                        手机：全屏抽屉（顶部 tab 横滑）
│       │                        平板：右栏常驻（tab 自动换行）
├── 判定 / 战斗演出 ............... 两端：居中覆盖层
└── 关于 / 合规声明 ............... 两端：弹窗
```

### 2.2 两端导航模型对照

| 能力 | 手机 | 平板 |
|---|---|---|
| 打开任意面板 | HUD 右上 `☰` 或底部「面板」→ 全屏抽屉 | 左导航栏图标常驻；右栏即时切换 |
| 面板之间切换 | 抽屉顶部 tab 条（可横滑） | 左导航栏直接点 / 右栏 tab 换行铺开 |
| 关闭面板 | 抽屉右上 `×` 或点遮罩 | 无需关闭（右栏常驻） |
| 回主菜单 | 抽屉无入口 → 关闭后走 HUD；**原型里**左栏底部「主菜单」 | 左导航栏底部「主菜单」 |
| 快速动作 | 行动轮盘 + 自由输入 | 同左，轮盘更宽（8 格） |

> 设计取舍：手机**不给底部 Tab 栏**。理由是游戏主循环里叙事流需要最大纵向空间，"常驻底栏"会永久吃掉 56dp；改成"抽屉 + 行动轮盘"后，叙事区拿到整屏，代价是面板多一次点击——对长时沉浸更划算。

## 4. 逐屏原型要点

### 4.1 主菜单

两级视觉：鎏金书法字「道渊」+ 冷紫/鎏金双光斑背景（`#boot-bg` 两层 radial-gradient 缓慢漂移）。按钮：开始仙途 / 继续游历 / 图鉴·百科 / 设置 / 关于。底部常驻**合规声明**（署名玖神、禁商用二传、内容与原作角色卡完全一致）。

### 4.2 游戏主界面 HUD

- **行 1**：姓名（鎏金）· 境界（冷紫，带 DC）· 右端 `☰`（手机）/ 无（平板已有左栏，`☰` 保留作抽屉触发不影响）。
- **行 2**：时间 / 地点 / 天气 / 危机四档徽标 / 遭遇冷却计数。
- **六维**：手机 3 列 2 行；平板 6 列 1 行。数值变化时对应条上方飘字（`+6` / `-18`），颜色取自该维度的条色。

### 4.3 叙事流

- 顶部**场景横幅**（当前时间/地点/危机）随最近回合更新。
- 消息气泡：助手（鎏金渐变左对齐）/ 玩家（冷紫右对齐）；助手正文**打字机**逐字出现（约 640ms 完成），末尾不污染 JSON——正文与状态彻底分离（对应主方案 4.3）。
- 效果 chip：`灵力 +6`（绿）/ `生命 -18`（红），只显示六维与好感/亲密这类"玩家关心的数值"。
- 行动建议：虚线胶囊按钮，点一下即作为玩家输入发出。
- **心声**：道侣/灵宠面板里的 `心声` 用左侧冷紫竖线引用块 + 淡入模糊动画呈现（"浮字"演出）。

### 4.4 行动区

| 按钮 | 行为 |
|---|---|
| 探索 | 引擎推进一步（时间前进、遭遇冷却 −1），LLM 生成叙事 |
| 修炼 | 本地结算：按灵根品阶给修为增量、时间推进 7 日、灵力回复 |
| 突破 | 弹**判定演出**覆盖层（不消耗 token 做算术） |
| 交流 | 场景内社交推进 |
| 玉简 / 地图 / 背包 | 直接打开对应面板 |
| 面板 | 打开当前面板（手机抽屉 / 平板右栏） |

> **遭遇冷却归零**时，下一次行动触发的不是普通回复，而是**动态遭遇事件**（原型里内置一条"狐族现身"示例），对应卡内 `遭遇冷却=0 → 抽取 RANDOM_NPC` 的机制。

### 4.5 判定 / 战斗演出（覆盖层）

居中卡片：己方 DC ↔ 敌方 DC、境界差、**引擎掷骰给出的胜率**（由道心/灵力/境界差算出）、结果「胜 / 败」大字、压制阶梯描述。点「承认结果」后生成一回合叙事。

这一屏是"引擎算、模型演"的可视化证明：**面板上的数字没有一个来自 LLM**。

### 4.6 面板清单（× 11）

| 面板 | 手机呈现 | 平板呈现 | 关键可视化 |
|---|---|---|---|
| 主角 | 抽屉 | 右栏 | 六维条 · 灵根徽记 · 气运卡（真·描金）· 功法器物 · 炼丹炼器 |
| 道侣 | 抽屉 | 右栏 | 亲密心形串 + 五维条 + **心声浮字** |
| 人物 | 抽屉 | 右栏 | 好感条 + **关系五阶阶梯**（陌生→试探→松动→信任→至诚） |
| 灵宠 | 抽屉 | 右栏 | 亲密度 + 心声 |
| 机遇 | 抽屉 | 右栏 | 任务卡（难度徽标/目标/机缘/引言），最多 20 条 |
| 绝色榜 | 抽屉 | 右栏 | 图鉴式卡片网格，未遇显示 `？？？` 半透明锁定 |
| 玉简 | 抽屉 | 右栏 | **手机外形壳** + 聊天气泡 + 传讯输入（发信触发 LLM 回信） |

| 设置 | 抽屉 | 右栏 | 模型档位 / 内容尺度（与原作一致，常开） / 神视模式 / 流式 / 前缀缓存 + **安卓适配自检** |

## 5. 安卓技术落地

### 5.1 外壳选型

主方案推荐 **Tauri 2**（Rust 芯 + 系统 WebView）。安卓端结论保持，但要点不同：

| 方案 | 安卓表现 | 评价 |
|---|---|---|
| **Tauri 2（推荐）** | 用系统 WebView（Chrome/WebView 内核），APK 约 10–20MB | 体积小、可直接复用本原型的 HTML/CSS/JS，Rust 侧做存档/文件/网络 |
| Capacitor | 打包 WebView，生态成熟、插件多 | 备选；优点是与现有 Web 资产零改动，体积略大 |
| Flutter 自绘 | 与现有 PocketTavern 工程一致 | **不推荐**：本作核心是富排版/复用卡内 HTML/CSS，Flutter 要重写一遍视觉 |

**关键约束**：系统 WebView 版本决定 CSS 可用性。本项目用到的 `env(safe-area-inset-*)`、`dvh`、`flex/grid`、`backdrop-filter` 在 **Android 7+ 的 WebView（Chrome 51+）** 上均可用；`backdrop-filter` 在极老机型会降级为无模糊（可接受）。因此**不要**依赖容器查询（Container Queries）做版式判定——本原型用 JS 计算宽度 + `data-layout` 属性，兼容性最稳。

### 5.2 安卓系统集成清单

| 项 | 做法 |
|---|---|
| **返回键 / 返回手势** | 拦截：开着抽屉 → 关抽屉；在面板 → 回叙事；在主界面 → 弹"退出到主菜单？"；在主菜单 → 二次确认退出 APP |
| 状态栏 | 沉浸式 + 透明，`theme-color: #0d1220`；HUD 用安全区让位 |
| 横竖屏 | 不锁定；旋转时保留滚动位置与当前面板 |
| 存储 | **全部本地**：`save-<id>/` 四文件（meta/state/chat/world，见附录 B.5）；不上云、不联网（除用户自配的 LLM 端点） |
| 权限 | 只需 **INTERNET**（调用户自己的 API）；不需要存储权限（用应用私有目录）；不上传诊断 |
| 包体预算 | APK ≤ 25MB（含中文字体子集）；世界书/规则表以 JSON 内置，约 1–2MB |
| 离线 | 除 LLM 调用外全离线可用；字体、图标用本地资源，**不引 CDN**（原型已做到零外链） |
| 保活 | 叙事流式请求期间禁止息屏（`FLAG_KEEP_SCREEN_ON`） |

### 5.3 性能预算

- 叙事流列表用**虚拟滚动**（长局可达数百条），消息 DOM 只保留可视区。
- 数值飘字、打字机用 CSS 动画 + 定时器，避免每帧 JS。已设 `prefers-reduced-motion` 时可关（建议实现时补）。
- 检索索引（319 条）常驻内存，冷启动构建一次并缓存到私有目录。
- 目标：中端机（骁龙 6 系）稳定 60fps 滚动；首屏可交互 < 1.5s。

### 5.4 字体与素材

- 中文标题用书法体（`Ma Shan Zheng` 或同族），正文 `Noto Serif SC`。**必须做子集化**（常用 3500 字 + 书名号等符号），否则单字体就 5–10MB。
- 卡内引用的 CDN 图与音频需逐个确认授权（主方案第 8 节）；原型不引用任何外部素材。

```
prototype/
```

- **可点的地方**：主菜单按钮、创角六步、行动轮盘、行动建议胶囊、面板 tab、玉简发信、设置开关、判定覆盖层。
- 原型**不连 LLM**，所有叙事为内置示例文本；数值变化由本地逻辑真实计算（体现"引擎算、模型演"）。
