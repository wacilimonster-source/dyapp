# 全量代码审查与测试报告

> 日期：2026-10-12　范围：`prototype/`（前端全部模块）＋ `app/src-tauri/`（Rust 壳全部模块）
> 方法：两路并行只读审查（前端 / Rust）→ **逐条自行复现核实** → 修复 → 补回归测试 → 实测验证
> 结论：**报出 18 条真 bug，已修 18 条；另有 6 条复核后判定为误报并撤回；8 条已知限制未修（附原因）**

---

## 0. 一句话结论

这一轮最有价值的不是"改了多少"，而是**改掉了三个会让游戏玩不下去或悄悄丢东西的问题**：

1. **突破成功后境界从不前进** —— 核心成长循环断掉（修为清零、境界永远停在创角那一层）。
2. **数值飘字整条链路是死代码** —— 写着这个特性，但从没有一处调用它。
3. **密钥文件一旦损坏就被静默当成"没配过"** —— 用户以为应用忘了他的 Key，重新填写还会覆盖掉可恢复的旧文件。

第 3 条尤其值得说：它的危害不是"报错"，而是**不报错**。

| **B4** | **Esc 关判定层跳过收尾回调**：`showJudge` 只在按钮点击里跑 `onAck`，Esc 分支直接隐藏覆盖层 | 该回合状态**已落地**但叙事没写进流、也没存档 → 数据与界面脱节，且那个气泡永远停在"打字中" | 记录待确认回调，Esc 与按钮走同一条路径 |
| **R1** | **密钥解密失败被静默吞**：`if let Ok(Some(bytes)) = read_sealed(..)` 把 `Err`（文件在但解不开）与 `Ok(None)`（没文件）一起跳过 → 静默变成"未配置"，且重新填写会**覆盖掉可恢复的旧文件** | 用户以为"应用忘了我的 Key"，无从排查；恢复窗口被销毁 | `Err` 单独分支：记日志 + 通过 `MaskedSecrets.decryptError` 传到界面，模型面板显示醒目的"密钥文件无法解密"卡与原因 |

| **R3** | **`state.json` 损坏静默变 `null`**（`unwrap_or(Value::Null)`），而同一份存档的 `meta.json` 损坏却是报错 | 前端拿到空状态可能触发"重置式覆盖"，把损坏升级成丢档 | `state.json` 损坏 → 返回可读错误并提示用「导入」恢复；`world.json`（附属数据）仍容错但留痕 |

## 2. 复核后撤回的误报（6 条）

审查报告里有些结论我没有直接采信，逐条复读源码后**判定不成立**，在此记录以免后人重踩：

| 误报 | 复核结论 |
|---|---|
| "`crypto.rs` 的 `blob[..4]` / `blob[5..17]` 可能越界 panic" | **不成立**。每处切片前都有长度校验（`len < 5`、`len < 5+12`），`is_sealed` 也先判 `len > 4`。全仓再无未加保护的切片 |
| "AEAD 的 nonce 可能不是随机" | **不成立**。`aead_seal` 每次 `getrandom(&mut nonce_bytes)`，非固定值、非计数器 |
| "capabilities 缺权限、前端命令未注册" | **不成立**。`bridge.js` 的 29 个 command 全部在 `lib.rs` 注册；窗口默认 label `main` 与 capability 的 `windows: ["main"]` 一致 |
| "`git_blob_sha` 可能因换行规范化误判、导致重复上传" | **不成立**。hash 前统一走 `redact_for_transfer` + `to_vec_pretty`，重序列化确定性成立 |
| "平板正文行宽 41 字过宽，需限宽 720px" | **撤回**（详见 [docs/07](07-交互优化设计.html) §1.5）。那是按栏宽算的；助手气泡有 `max-width:78%`，实测 29 字/行，本就在舒适区间 |
| "版式判定只依赖 resize 是产品 bug" | **降级**（详见 docs/07 §1.6）。装探针复测发现改视口时 `resize`/`ResizeObserver`/`visualViewport` 三个事件都不触发——是自动化环境的假象，未在设备上复现；改动保留但理由换成软键盘/分屏 |

## 3. 已知限制（**本轮未修**，附原因）

| # | 限制 | 为什么没修 | 建议 |
|---|---|---|---|
| L1 | **存档四文件非事务**：四个文件各自原子写，进程在中间被杀会出现"state 新、chat 旧" | 真正的跨文件原子需要"临时目录整体替换"或 journal，改动面与风险都大，不适合和这批 bug 一起上 | 优先级最高的一条：先把 `meta.updatedAt` 放到最后写（现在已是最后），再考虑目录级替换 |
| L2 | `sync_push` 的 `force` 会覆盖远端且**不做远端备份** | 远端是 git，历史可回滚；应用内备份需要额外一次读回 | 与 L1 一起做 |
| L3 | `pick_slot` 中 `overrides` / `use_arbiter` / `sampling` 三者优先级未明确（`overrides` 会短路 `use_arbiter`） | 当前前端只发 `sampling`，不触发；属对外契约的清理 | 若日后开放 `overrides`，先定优先级 |
| L4 | Windows 与非 Windows 之间密钥文件**不能互相解密** | 这是设计（DPAPI 与 AEAD 本就不同）；本轮已让提示可读 | 若要跨设备，同步的是"重新填一次 Key"，不是密文 |
| L5 | 长局叙事流**没有虚拟滚动** | 性能优化，非缺陷 | 回合数上到数百时再做 |
| L6 | `save.rs` 读操作会顺带创建目录（`save_dir → ensure_dir`），空目录会被列进"本地存档" | 影响小 | 列表时过滤掉没有 state.json 的（已做）／读取路径改为不建目录 |
| L7 | 时间线回看、成就、存档缩略图 | 既有欠账，与本轮无关 | 见主方案 M6 |
| L8 | `Cargo.toml` 里 `uuid` 与 `tokio` 的 `fs/sync` feature 未被库代码使用 | 清理项 | 移到 `[dev-dependencies]` 或删除 |
