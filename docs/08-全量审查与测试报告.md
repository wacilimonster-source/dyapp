## 0. 一句话结论

这一轮最有价值的不是"改了多少"，而是**改掉了三个会让游戏玩不下去或悄悄丢东西的问题**：

1. **突破成功后境界从不前进** —— 核心成长循环断掉（修为清零、境界永远停在创角那一层）。
2. **数值飘字整条链路是死代码** —— 写着这个特性，但从没有一处调用它。
3. **密钥文件一旦损坏就被静默当成"没配过"** —— 用户以为应用忘了他的 Key，重新填写还会覆盖掉可恢复的旧文件。

第 3 条尤其值得说：它的危害不是"报错"，而是**不报错**。

## 2. 复核后撤回的误报（6 条）

审查报告里有些结论我没有直接采信，逐条复读源码后**判定不成立**，在此记录以免后人重踩：

| 误报 | 复核结论 |
|---|---|
| "`crypto.rs` 的 `blob[..4]` / `blob[5..17]` 可能越界 panic" | **不成立**。每处切片前都有长度校验（`len < 5`、`len < 5+12`），`is_sealed` 也先判 `len > 4`。全仓再无未加保护的切片 |
| "AEAD 的 nonce 可能不是随机" | **不成立**。`aead_seal` 每次 `getrandom(&mut nonce_bytes)`，非固定值、非计数器 |
| "capabilities 缺权限、前端命令未注册" | **不成立**。`bridge.js` 的 29 个 command 全部在 `lib.rs` 注册；窗口默认 label `main` 与 capability 的 `windows: ["main"]` 一致 |
| "`git_blob_sha` 可能因换行规范化误判、导致重复上传" | **不成立**。hash 前统一走 `redact_for_transfer` + `to_vec_pretty`，重序列化确定性成立 |
| "平板正文行宽 41 字过宽，需限宽 720px" | **撤回**（详见 [docs/07](07-交互优化设计.html) §1.5）。那是按栏宽算的；助手气泡有 `max-width:78%`，实测 29 字/行，本就在舒适区间 |
| "版式判定只依赖 resize 是产品 bug" | **降级**（详见 docs/07 §1.6）。装探针复测发现改视口时 `resize`/`ResizeObserver`/`visualViewport` 三个事件都不触发——是自动化环境的假象，未在设备上复现；改动保留但理由换成软键盘/分屏 |

## 3. 上轮遗留限制的处理结果

上一轮留下 8 条"已知限制"，本轮逐条过了一遍：**5 条已修（L1/L2/L3/L6/L8）**，3 条经复核判定**不该修**（L4 是设计、L5/L7 是欠账而非缺陷），另有 4 个可优化点顺手做掉。

### 3.1 本轮已修

| # | 上轮状态 | 修法 | 验证 |
|---|---|---|---|
| L1 | 四文件各自原子写，中间被杀会得到"state 新、chat 旧" | `write_bundle` 改为**临时目录整体换盘**：四个文件先写 `<id>.tmp-writing/`，再 `rename(<id> → <id>.old-backup)` + `rename(tmp → <id>)`，失败回滚；新增 `heal_save_dir()` 在每次读写前收拾残骸（见 `.old-backup` 而 `<id>` 不在 = 崩在换盘中间，把旧档换回来）；读路径改用 `save_dir_existing`，不再顺带建目录 | Rust 单测 5 项：**写入后读回一致且不留残骸**、**崩在换盘中间时回滚到上一版**（断言回到 `灵力=11` 而不是读空）、**写入前残留的临时目录不会干扰这次写入**、**连续写入只保留最新一版**（断言 `turns` 不混入上一版的行）、残骸命名判定 |
| L2 | `force` 覆盖远端不做备份 | `sync_push` 在 `force` 时先逐个比对 git blob SHA，**内容真的不同**才把远端那版下载到存档目录里的 `remote-backup-<时间戳>/`，并在返回值里带 `remoteBackup` 名字；与 `sync_pull` 覆盖本机前会备份本地对称 | 逻辑与 pull 侧同源；`git_blob_sha` 相等则跳过，不会为"其实没变"的文件白备份 |
| L3 | `overrides`/`use_arbiter`/`sampling` 优先级没写明 | 在 `pick_slot` 上写明契约：**overrides 决定"用哪个模型"，sampling 决定"怎么采样"**；两者同时给出时 `eprintln` 告警并明确以 overrides 为准 | 代码内文档化 + 运行时告警；前端当前只发 `sampling`，行为不变 |
| L6 | 读操作建目录 → 空目录混进"本地存档" | 新增 `paths::save_dir_existing`（只解析不创建）；`save_list` 与 `sync_push_all` 都跳过 `.tmp-writing`/`.old-backup` 残骸（`is_save_dir_name`） | 单测锁定命名判定；空目录不再出现在列表，也不会被批量推送 |
| L8 | `uuid` 依赖未使用、`tokio` 只被测试用到 | 删掉 `uuid`；`tokio` 移到 `[dev-dependencies]`（库代码不直接依赖它） | `cargo check` 干净通过；依赖图里不再拖 `tokio::fs/sync` |

### 3.2 复核后判定"不修"（附理由）

| # | 项 | 为什么保留 |
|---|---|---|
| L4 | Windows 用 DPAPI、其他平台用 ChaCha20-Poly1305，**密文不能互解** | 这是设计要求，不是缺陷：两个平台的密钥保护机制本来就不同。跨设备的正确做法是"在新设备重新填一次 Key"，不是搬运密文 |
| L5 | 长局叙事流没有虚拟滚动 | 性能优化，非缺陷。回合数上到数百时的体验问题，等有实测数据再做 |
| L7 | 时间线回看 / 成就 / 存档缩略图 | 功能欠账，与缺陷无关，见主方案 M6 里程碑 |

## 6. 后续建议顺序

第一轮列的四条按顺序做完了：L1（存档跨文件原子性，本轮唯一还"可能丢进度"的一条）、L2（force 推送的远端备份）、L3/L6/L8（契约清理、读路径副作用、依赖清理）。

现在真正剩下的都是**欠账而非缺陷**，按收益排：

1. **L5 虚拟滚动** —— 叙事流到数百回合后的滚动与内存，等有实测数据再动。
2. **L7 时间线回看 / 成就 / 存档缩略图** —— 主方案 M6 的功能里程碑。
3. `renderSidebar` 局部化、`crypto.rs` 错误码分类 —— 顺手项。

一句话：**当前没有"会丢进度、会玩不下去、会静默失灵"的已知问题。** 剩下的都是体验和功能，不是坑。
