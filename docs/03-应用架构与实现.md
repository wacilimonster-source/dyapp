## 1. 结论：一套代码，三个形态

用 **Tauri 2** 做壳，前端直接复用已有的 Web 界面：

| 形态 | 产物 | 说明 |
|---|---|---|
| Windows 桌面 | `dyapp.exe` / `.msi` / `-setup.exe` | 长时沉浸游玩的主场景 |
| 安卓手机 | `app-universal-release.apk` | 与平板**同一个 APK**，按屏幕宽度自动切版式 |
| 安卓平板 | 同上 | 已适配横竖屏与安全区 |

**为什么是 Tauri 2**（延续主方案第 6.5 节的判断，这里补上实测依据）：

- 富排版 / 动画 / 复用卡内 HTML+CSS 是本作的核心，Web 前端优势最大；Flutter 要重写一遍视觉。
- 体积小：Rust 芯 + 系统 WebView（安卓用系统 WebView，Windows 用 WebView2），不用打包 Chromium。
- 安卓与桌面共用同一套 Rust 业务代码，`cargo tauri android build` / `cargo tauri build` 两条命令出两端。
- 反例：Electron 在安卓上没有官方路径；Capacitor 桌面端要再叠一层 Electron，变成两套壳。

## 3. 分层与职责

严格按"能本地算的绝不交给模型"来切：

| 层 | 语言 | 职责 |
|---|---|---|
| **界面层** | 原生 HTML/CSS/JS（`prototype/`） | 叙事流、HUD、面板、演出。**不含任何密钥** |
| **壳能力层** | Rust（`app/src-tauri/`） | 大模型请求、密钥保管、存档读写、GitHub 同步 |
| **规则/状态层** | TS（前端，后续从 `app.js` 拆出） | 数值 clamp、境界查表、掷骰、遭遇抽取 |
| **叙事层** | 前端拼提示词 → 壳发请求 | 正文由模型产出 |

这样切的收益：**密钥与网络都在 Rust 侧**，WebView 里跑的任何脚本都拿不到 API Key；同时界面层保持纯静态，浏览器里能直接预览（降级）。

### 3.1 桥接协议

`bridge.js` 是唯一通道，界面代码不写 `if (isTauri)`，只问 `DYApp.available()`：

```js
DYApp.available()                      // 是否在壳里
DYApp.llm.get() / set(settings)        // 模型配置
DYApp.llm.setKey(k) / clearKey()       // Key 单独入口
DYApp.llm.models()                     // GET {base}/models
DYApp.llm.stream(req, onEvent)         // 流式对话
DYApp.llm.completeJson(req)            // 非流式，要求严格 JSON
DYApp.sync.getConfig() / setConfig()   // 同步配置
DYApp.sync.setToken / clearToken
DYApp.sync.localSaves() / remoteSaves()
DYApp.sync.push(id, force) / pull(id, force) / pushAll()
```

在浏览器里这些调用统一抛"需要在客户端内运行"，界面显示提示卡而不报错。

## 4. 大模型客户端（参照 PocketTavern，但只留必需）

参考对象是同一工作区里的 **PocketTavern / LettuceAI**（Flutter + Tauri 的现有实现）。沿用的约定：

| 沿用 | 具体 |
|---|---|
| `ProviderConfig` 形状 | `id / name / base_url / endpoint_path / system_role / supports_stream / requires_api_key / default_headers` |
| 统一传输层 | 一个地方建 `reqwest::Client`，流式与非流式共用超时、UA、Header 组装 |
| 流式事件规范化 | 增量统一成 `delta` / `reasoning` / `usage` / `done` / `error` 五类，前端只认这五类 |
| 双模型档位 | 叙事模型（主）+ 裁决模型（辅，可选），分别配置 |
| 导出剥离密钥 | 参考其"备份时剥离 apiKey/proxy"的做法，落到 `redact_for_transfer` |

**刻意不做的**（`只需要支持本项目用到的部分`）：

- 多 provider 适配层（Anthropic / Gemini / Claude 原生协议）——本项目只走 OpenAI 兼容；
- 工具调用循环（tool-calling loop）、MCP、图片/语音/TTS/ASR、本地 llama.cpp 与 embedding；
- 用量计费、价格缓存、地区路由、TLS 证书例外等运维级能力。

**保留的能力只有四项**：

1. `POST {base_url}/chat/completions` 流式（SSE）—— 叙事正文；
2. 同上非流式 + `response_format: {"type":"json_object"}` —— effects 抽取；
3. `GET {base_url}/models` —— 设置页"测试连接 / 拉取模型"；
4. 两个模型槽位 + 采样参数 + `extra_body` 透传（给 prompt caching / `enable_thinking` 这类厂商私有字段留口）。

### 4.1 实测得到的两条硬约束（2026-10-12，用 opencodego 渠道 + deepseek-v4.1-flash 跑通）

拿真实渠道打过之后暴露了两件靠读文档不会知道的事，都已修进代码：

| 现象 | 结论 | 落到的改动 |
|---|---|---|
| `stream:false` 的请求**挂住不返回**（90s 超时、0 字节） | 该渠道只可靠支持流式 | `llm.rs` 删掉非流式分支，**一律流式累积**；"要 JSON"的裁决调用也走流式，再把整段当 JSON 解析 |
| 缺 `x-opencode-session` 头时返回 `400 MissingSessionID` | 需要会话标识头 | 新增 `opencodego` 预设；模型面板加「附加请求头」文本框（每行 `名: 值`），选中该预设会自动补一条随机会话 ID |

另外该模型的思维链走 `reasoning_content` 字段，客户端**只取 `content`**（按卡设定不展示思考），
这一点在测试里踩过一次坑：测试适配器误把 `reasoning_content` 也拼进正文，看起来像"模型在说英文分析"，
实际是测试代码的问题——修掉后正文是干净的中文修仙叙事。

**怎么自己复跑**（密钥只走环境变量，不落盘、不进 git）：

```bash
export DY_LLM_BASE_URL="https://opencode.ai/zen/go/v1"
export DY_LLM_API_KEY="<你的 key>"      # 只在这个 shell 里存在
export DY_LLM_MODEL="deepseek-v4.1-flash"
node --test tests/integration.live.test.mjs
```

不提供这三个变量时测试整体跳过，CI 因此永远不会碰到真钥。

### 4.2 流式实现要点

- 手工解析 SSE：按 `\n` 切行 → 取 `data:` 前缀 → `[DONE]` 结束 → 失败行静默跳过（兼容各家中转的多余空行）。
- 兼容 `reasoning_content` / `reasoning` 字段（DeepSeek / vLLM / OpenRouter 会把思维链放这里），按卡的设计**不展示**，只吞掉。
- 错误体解析：优先取 JSON 里的 `error.message`，避免把整页 HTML 塞进 UI。
- 超时 600s（长文），连接超时 30s；流式不设整体超时。

## 5. 密钥与隐私边界

需求原文：**"请求大模型的配置保留在本地不允许放在公网"**。实现上是三层防线：

| 层 | 做法 |
|---|---|
| **物理隔离** | API Key 与 GitHub 令牌只写 `<app_config_dir>/secrets.json`，**和模型配置 `llm.json` 分开**——`llm.json` 里根本没有 key 字段，不存在"顺手把整个配置文件传出去"的可能 |
| **不入传输** | 存档四件套（meta/state/chat/world）不含密钥；推送前再跑一遍 `redact_for_transfer()`，递归删除 `apiKey / api_key / token / authorization / secret` 等字段 |
| **前端只见掩码** | `llm_settings_get` 返回的是 `MaskedSecrets{ llmKeySet, llmKeyHint:"****abcd" }`，前端**永远拿不到明文**，也没有任何 command 能把明文读回去 |

### 5.1 静态加密（本地落盘也不留明文）

前三层解决"别传出去"，这一层解决"磁盘上别留明文"。实现在 `app/src-tauri/src/crypto.rs`：

| 平台 | 做法 | 强度 |
|---|---|---|
| **Windows** | DPAPI（`CryptProtectData`）。密钥材料由**当前登录凭据**派生 | 磁盘上不存在可窃取的密钥文件；拷到别的账户/机器都解不开 |
| **Android 及其它** | ChaCha20-Poly1305 + HKDF-SHA256。随机主密钥与盐单独存文件、与密文分离 | AEAD 保证改一个字节就解不开（可检测篡改） |

密文自带版本头（`DYA1`/`DYA2`），日后换算法可平滑迁移。旧版本的明文 `secrets.json`
在首次启动时**自动加密后就地删除**。

**威胁模型要说清楚**（`crypto.rs` 顶部也写了）：

- 防住：磁盘/备份里出现明文 Key；有人拷走配置文件就能直接用；随手把配置发出去。
- 防不住：攻击者能以**你的用户身份**在本机执行代码。那种情况下任何本地加密都能被解开——
  这是本地存储的固有限制，不是本模块的缺陷（要更强就得把请求放到服务端）。
- 下一步：安卓接 **Android Keystore**（硬件保护），Windows 已是 DPAPI，无需再加。

### 5.2 仓库守卫（防"手滑提交"）

`.gitignore` 只能挡住"文件被加进来"，挡不住"有人把 Key 粘进源码/文档/配置里"。
因此 `tests/repo.hygiene.test.mjs` 会扫描**所有被 git 跟踪的文件**，命中
`sk-…` / `ghp_…` / `github_pat_…` / `AKIA…` / `AIza…` / `xox…` 这类密钥形态即失败，
并校验敏感文件（`secrets.*`、`install.key`、`*.keystore` 等）未被跟踪。已接进 CI。

补充：

- 安卓上 `app_config_dir` 位于**应用私有目录**（`/data/data/com.wacilimonster.dyapp/`），其它 App 无 root 读不到；`secrets.json` 在 unix 侧另设 `0600`。
- 能力声明只开 `core:default / core:event / core:window / core:app`——**没有** fs、shell、http 插件权限，WebView 侧拿不到通用文件与网络能力。
- CSP 收紧到只允许 `self` + `api.github.com`（检查更新用）；大模型域名不列在 CSP 里，因为请求是 Rust 发的，不经过 WebView。

## 6. 多端进度同步（GitHub 当同步盘）

### 6.1 为什么是 GitHub

用户自带账号 → 零服务端、零成本、天然版本历史（每次同步一个 commit，可回滚到任意一次进度）。缺点是依赖第三方可用性，以及需要用户自己建仓库和令牌。

### 6.2 远端布局

```
<你的仓库>/
└── saves/                     # basePath，可配
    ├── save-01/
    │   ├── meta.json          # 版本/时间/摘要/缩略图
    │   ├── state.json         # GameState（结构化状态）
    │   ├── chat.jsonl         # 叙事流（每行一回合）
    │   └── world.json         # 已解锁图鉴/人物/足迹
    └── save-02/…
```

本地布局与之同构，均在 `<app_data_dir>/saves/<id>/`。

### 6.3 同步行为

- **推送**：逐文件算 git blob SHA-1（`sha1("blob <len>\0"+content)`）与远端 `sha` 比对，**内容没变就跳过**——避免每次同步都造一个空 commit。
- **冲突**：以 `meta.updatedAt` 判定。默认"后来者胜"：本地更新则拒绝拉取、远端更新则拒绝推送，并明确提示"请先拉取/推送，或强制覆盖"。**不静默丢档**。
- **覆盖前备份**：拉取覆盖本地前，把本机四件套另存为 `conflict-<时间戳>/`，事后可手工找回。
- **令牌权限**：只需目标仓库的 **Contents: Read and write**。建议用**私有仓库**。

### 6.4 未做（明确记录）

真正的**逐回合合并**（两端各自推进后合并成一条时间线）没有做——v0.1 是"整档后写胜"。要做的话需要给 `chat.jsonl` 加回合级 UUID + 向量时钟，属于独立课题。

**⚠️ 产物是未签名的**，不能直接安装：

```bash
# 产物：app/src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release-unsigned.apk
BT="G:/Android/build-tools/35.0.0"          # 换成你本机的 build-tools 版本
cd app/src-tauri/gen/android/app/build/outputs/apk/universal/release
cp app-universal-release-unsigned.apk /tmp/aligned.apk
"$BT/zipalign.exe" -f -p 4 /tmp/aligned.apk /tmp/signed.apk
"$BT/apksigner.bat" sign \
  --ks ~/.android/debug.keystore --ks-pass pass:android \
  --key-pass pass:android --ks-key-alias androiddebugkey \
  --out dyapp-0.1.0-universal.apk /tmp/signed.apk
"$BT/apksigner.bat" verify --print-certs dyapp-0.1.0-universal.apk   # 校验
```

用 debug keystore 签出来的包**可以侧载安装**，用于自测与私人使用；正式分发必须换成自己的 keystore（见 8.3）。

## 8. 已知限制与下一步

### 8.1 功能缺口（按优先级）

1. **effects 闭环未接**：目前叙事走大模型，但状态变更仍由前端本地模拟。下一步是把 `llm_complete_json` 接上裁决模型，让它按 [附录B](附录B·状态数据模型.md) 的语义 effect 协议输出 `effects[]`，再由引擎落地。
2. **引擎未从 `app.js` 拆出**：规则/状态目前和界面混在一个文件里，未做到主方案要求的"内核可单测"。应拆成 `engine/` 纯 TS 包 + `tests/`。
3. **存档未接**：Rust 侧已有目录约定与同步读写，但界面还没有"存档列表 / 手动存档 / 读档"入口。
4. **世界书检索未做**：319 条仍是静态数据，未建索引、未做 Top-K 注入。
5. **`prototype/` 改名 `web/`**（见第 2 节命名欠债）。

### 8.2 工程化缺口

- CI 还没有 Rust 构建任务（Tauri 在 Linux runner 上要装 `libwebkit2gtk-4.1-dev` 等系统依赖，需要专门写一个带缓存的 workflow）。
- `release.yml` 目前只发布原型 zip；安卓壳与 Windows 产物接入后应改为随 Release 上传 APK/MSI，这样「检查更新」的下载按钮才真正可用。
- 未做 Android 返回键拦截（原型设计文档第 5.2 节已定义行为），需要在壳侧监听返回事件。

### 8.3 分发

- **成人向内容 + 主流应用商店**：Google Play 不接受，分发只能侧载 APK 或自有渠道。因此更新必须自建（本项目的「检查更新」读 GitHub Releases，正好绕开商店）。
- **正式签名**：上架/长期分发前需生成自己的 keystore：
  ```bash
  keytool -genkey -v -keystore dyapp.keystore -alias dyapp \
    -keyalg RSA -keysize 2048 -validity 10000
  ```
  然后在 `gen/android/keystore.properties` 配置，**keystore 与密码绝不入库**。
