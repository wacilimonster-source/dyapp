## A.2 世界书（319 条，约 20.4 万字）

**统计**：总条目 319 · 正文合计 203,627 字 · `constant`（常驻）55 条 · `enabled` 294 条 · 带触发 `keys` 269 条。
**注入结构**：绝大多数条目 `depth=4`；`位置` 分 `before_char`（常驻设定，进系统侧）与 `after_char`（按 key 触发/按需）；少数 `depth=0~3` 用于状态栏与审查。

### 关键机制条目

| 条目 | 作用 |
|---|---|
| `[initvar] 初始` | 开局变量初值（世界/主角/道侣/灵宠/人物/机遇/绝色榜/玉简） |
| `[mvu_update]变量输出格式` | 规定模型每回合输出 `<UpdateVariable>` + JSON Patch（replace/delta/insert/remove），路径**必须**以 `/` 开头、中文路径、0–100 钳制 |
| `[mvu_update]` | 变量更新总则（首回合必须全量初始化、每回合必须更新时间/地点/危机/遭遇冷却） |
| `变量列表` | 注入 `{{format_message_variable::stat_data}}` 当前变量快照 |
| `状态栏` | 旧版 `<data_block>` 输出格式（当前 `enabled=false`，被 MVU 状态栏取代） |
| `具体数值` | 五大资源定义、模糊感知对照、突破机制、修炼耗时、灵根品阶修炼加成表 |
| `DC点数判定` | 境界鸿沟铁则 + DC 差压制阶梯（0-2/3/6/9/15/≥30）+ 全境界 DC 总表 |
| `道心值设定` | 道心四境、涨跌规则、初始值、道心共鸣、心魔劫 |
| `合理性审查` | 三重人格（审理 30 条铁律 / 衡平 / 天道）+ 强制思维链反偷懒协议（当前 `enabled=false`） |
| `-内容控制开关-玄天界/仙界 (二选一)` | 用 EJS `getwi()` 按需拉取被禁用的世界书条目，实现"开关注入" |
| `玄天界/仙界动态人物相遇` | 遭遇逻辑：`遭遇冷却>0` 禁止偶遇；`=0` 时按境界与场景（室内/室外）抽取 `[RANDOM_NPC]` |

### 值得注意的设计

1. **EJS 按需注入**：大量常驻设定条目 `enabled=false`，由 `内容控制开关` 条目用 `<%- await getwi(null, 'xxx') -%>` 动态拉取——**卡本身已在做一种"检索注入"**，只是粒度粗（整块开/关），独立版可以做得更细。
2. **世界书即数据库**：178 条人物卡 + 34 势力 + 24 地点 = 可直接转成 APP 的**图鉴/Wiki 数据源**（绝色榜、势力页、人物页）。
3. **双界切换**：玄天界/仙界两套设定通过开关二选一，独立版对应"出生界"与"飞升"。

## A.5 变量模型（Zod Schema）

`ZOD` 脚本用 `registerMvuSchema` 定义了八大块（完整字段见 `附录B`）：

```
世界 { 当前时间, 当前地点, 危机程度, 遭遇冷却, 动向{} }
主角 { 姓名, 性别, 容貌, 身形, 衣着, 境界, 宗门, 宗门贡献, 所在界,
       生命, 精血, 灵力, 修为, 神识, 道心, 神念, 气运{}, 灵根, 状态,
       炼丹{}, 炼器{}, 储物袋{}, 功法{}, 器物{} }
道侣 { <姓名>: { 性别, 种族, 状态, 境界, 亲密, 生命, 灵力, 修为, 道心,
                性格, 外观, 身高, 背景, 神通, 心声 } }
灵宠 { <姓名>: { 性别, 种族, 境界, 生命, 灵力, 修为, 亲密度,
                性格, 容貌外观, 神通, 状态, 心声 } }
人物 { <姓名>: { 性别, 头衔, 境界, 好感, 关系阶段, 生命, 灵力, 修为, 道心, 性格, 描述 } }
机遇 { <任务名>: { 难度, 目标, 机缘, 引言 } }        # 保留最近 20
绝色榜 { <姓名>: { 排名, 头衔, 仙姿, 群芳谱 } }
玉简 { <好友>: { 性别, 境界, 关系, 好感度, 历史记录{} } }   # 历史记录保留最近 100
$器灵台词: string[]
```

**Schema 里的"防御性编程"**（独立版可直接继承）：
- 全部数值 `z.coerce.number().catch().transform(clamp 0~100)`；
- 枚举 `z.enum([...]).catch()`；对象 `.catch({}).prefault({})`；
- 英文 key 自动归一化为中文（`type→类型 / description→描述 / location→地点`）；
- `储物袋`：`数量>0` 自动筛选；`机遇`：`takeRight(20)`；`玉简.历史记录`：`takeRight(100)`。

## A.6 开局流程（实测）

```
消息0 · swipe0  = 欢迎页 HTML（烟花 + 版权 + 使用说明）
      │  点击「开始仙途」→ switchToSecondGreeting()
      ▼
消息0 · swipe1  = "[重塑仙缘]"（6 字占位）
      │  正则8 把 [重塑仙缘] 替换成 185,362 字创角界面
      ▼
创角界面（分步：身份/灵根/气运抽取/天定道侣/出生地…）
      │  确认后拼装 sysMessage
      ▼
triggerSlash(`${sysMessage} | /cut {msgId} | /trigger`)
      │  剪掉 UI 消息 → 触发 AI 第 0 回合
      ▼
模型输出：开局叙事 + 状态栏 + <UpdateVariable> 首次全量初始化
```

创角界面内容规模（185K 字）含：气运池数组（女性向/男性向/通用）、灵根品阶概率表、天定道侣生成、粒子动画、悬浮配置、以及"告道渊同胞书"内置作者声明。

## A.7 每回合协议（实测）

| 环节 | 内容 |
|---|---|
| 提示词注入 | 世界书 constant 条目 + `变量列表`（当前 snapshot）+ 近况 + `[mvu_update]变量输出格式` |
| 模型输出 | 正文叙事（可含 `[System]`/状态栏） + `<UpdateVariable><Analysis>…</Analysis><JSONPatch>[…]</JSONPatch></UpdateVariable>` |
| 变量落地 | MVU 解析 JSONPatch，Zod Schema 校验/clamp 后写入当前楼层变量 |
| 渲染 | 正则6 把 `<StatusPlaceHolderImpl/>` 替换为绑定变量的状态栏 HTML |
| 遭遇 | `遭遇冷却>0` 则 -1 禁止偶遇；`=0` 触发抽取（正则9/10/13/14 注入候选） |

**每回合必须更新**：世界.当前时间 / 当前地点 / 危机程度 / 遭遇冷却；其余事件驱动。
